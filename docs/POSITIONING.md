# 定位与差异化 —— 和 TraceQuay / riftmark 的关系

问得好：聊下来 Datamora Attest 确实"听起来像"你们已有的两个平台。但三者是**同一个主题（信任/验证）在不同对象上的三个延伸**，不是竞争。

## 三个平台各自在验证什么

| 平台 | 验证对象 | 信任性质 | 典型场景 |
|---|---|---|---|
| **TraceQuay（溯岸）** | 组织里的**人/系统**做了什么（安全运营：调查、检测、响应、审计） | 内部记录 SHA-256 摘要 + 人工核验 | SOC 安全运营、案件调查、审计台账 |
| **riftmark** | **扫描/评估**的结果（nuclei 漏洞、agent/site 评估） | run-evidence 运行证据留存 | 安全评估、agent 运行时证据 |
| **Datamora Attest** | **自主 Agent 的链上决策**（它买了什么、谁授权的、模型是否真的算出了这个数） | 自验证回执 + EIP-712 授权签名 + 链上锚定 + 可验证推理 + x402 机器支付 | Agent 管钱、机器经济、付费信号 |

## 三个关键区别

1. **对象不同**：TraceQuay 验证"组织里的人/系统"，riftmark 验证"评估结果"，Attest 验证"自主 Agent 的链上决策"。后者是全新的对象——**机器替人做决定并花钱**。

2. **信任从"证据留存"升级为"机器信任协议"**：
   - TraceQuay 的审计 = 记录的 SHA-256 摘要（防篡改的证据），但**没有密码学授权绑定、不上链、不能被机器自动支付**。
   - Attest = 自验证（无需信任注册表）+ **EIP-712 签名授权**（谁授权可证明）+ **Merkle 链上锚定**（不可篡改时间戳）+ **可验证推理**（模型输出是真的）+ **x402 按次付费**（机器之间能自动结算）。

3. **场景不同**：安全运营 vs Agent 经济。Attest 面对的是"AI Agent 开始自己管钱"这个 2026 年的新问题。

## 一句话定位

> 你们团队已经在做"验证/证据"（TraceQuay 的审计、riftmark 的 run-evidence）。Datamora Attest 是把这套 DNA **下沉到「Agent 管钱」这个新场景**，并补上三块它们没有的：**密码学授权、链上锚定、机器支付**。

这不是撞车，而是同一支团队在同一主题上的能力延伸——这在黑客松叙事里反而是加分项：**"我们从安全运营做到 Agent 信任层"**。
