# 采访 / 答辩问题准备（随机提问应对）

> 原则：**不慌、不吹、诚实标边界。** 所有回答都能映射回 SECURITY.md 的"五条性质 + 信任根"。问到不会的，就诚实说"这是边界，写在这里"，比硬答强十倍。

## 开场（被问"你做了什么"的第一句）

> AI 已经在链上替人花钱了——问题不是它能不能花，是**凭什么信它**。我们做的是让自主 Agent 的每一次链上决策**可验证、可授权、可追责**，一条线：存证 → 授权 → 计算证明 → 数据来源证明 → 链上锚定 → 链上可验 → 机器付费。

---

## 一、定位与价值

**Q1：现在真有人需要吗？是不是太早？**
> 诚实说：这是 timing 判断。今天自主管钱的 agent 还不多，但 Agent 经济正在爆发，而"信任/追责"是它最缺的一层。我们在需求爆发前把基础设施铺好。这不是回避，是定位。

**Q2：和 EAS / 其他 attestation 方案有啥区别？**
> EAS 是通用声明协议，我们是"agent 执行"专用栈：把授权(EIP-712)、计算(可验证推理/zkML)、数据来源(链上存储证明)、锚定(Merkle)、机器付费(x402)打包成一条**自验证 receipt**。区别是"为 agent 管钱这个场景做深"。

**Q3：这不就是个审计日志吗？**
> 审计日志是"证据留存"，我们是"机器信任协议"——多了三样：**密码学授权**（谁授权可证明）、**链上锚定**（不可篡改+时间戳）、**机器自动结算**（x402）。对象也从"人"变成了"自主 agent"。

## 二、技术 / 科学性

**Q4：凭什么说安全？有证明吗？**
> SECURITY.md 五条性质，每条有论证+反例测试：S1 防篡改、S2 成员证明、S3 锚定时间戳、S4 授权、S5 决策真实性（拆 S5a 计算 + S5b 数据来源）。**每条都标了前提**，33 项测试全绿。

**Q5：你的 ZK 是真 ZK 吗？量化误差呢？**
> 真 Halo2 零知识证明（EZKL），在 Linux VM 上真跑通 `prove → verify: true`。诚实说：EZKL 把模型量化成定点电路，证明的是量化后的模型，输出有量化误差——这是 zkML 通病，不是我们的缺陷。

**Q6：怎么证明输入是真的、不是 agent 编的？**
> EIP-1186 链上存储证明。**自实现了 Ethereum MPT 验证器**，离线就能验证 receipt 里的 storage proof 对上区块 `stateRoot`——不信任任何预言机/数据源。信任根降到了"链本身"。

**Q7：如果 agent 撒谎 / 数据被攻破？**
> agent 撒谎：算数上 S5a 挡，数据上 S5b 挡。数据源被攻破：我们已经没有"数据源密钥"这个单点了，数据直接来自链上状态。剩下的信任只有链的共识。

**Q8：EIP-712 授权和 ERC-8004 什么关系？**
> 同源——都是"给 agent 行为划边界"。我们用 EIP-712 签 policy 哈希做最小可验证授权；ERC-8004 是标准化的 agent 授权/信誉框架，我们 receipt 的 consent 字段可直接映射过去。

## 三、架构 / 实现

**Q9：所有 proof 都上链吗？**
> 不。上链只锚**一个 Merkle root**（批量 receipt 的根）。单条 receipt 的 proof 链下生成，用 `verifyProof` 链上验成员关系。链上成本 O(1)，不随 receipt 数量增长。

**Q10：链上成本 / gas 多少？**
> `attest` 一笔 tx 存一个 bytes32 root + 时间戳，gas 极低；`verifyProof`/`verifyReceipt` 是 pure/view，零 gas。这就是批量锚定的好处。

**Q11：为什么选 Robinhood Chain？**
> 我们的 agent 就在 Robinhood Chain（Arbitrum Orbit L2）交易，存证锚定同一链、状态证明也读同一链，闭环。而且它是 ETH 生态 L2，符合 ETH Shenzhen。

**Q12：receipt 多了怎么扩容？**
> Merkle 聚合，锚定成本恒定；链下存 receipt，链上只存 root，可无限横向扩展。

## 四、落地 / 商业

**Q13：谁付费？怎么赚钱？**
> 第一个场景是 x402 按次付费信号：买方付费，同时拿到可验证 receipt 证明战绩真实。往后是 agent 审计、合规存证、机器间服务结算。

**Q14：demo 是主网还是本地？**
> 现场本地链（chainId 4663 镜像 Robinhood）真发交易，零风险零网络依赖；主网已部署 AttestationAnchor 作旁证（如已部署，附 tx + 浏览器链接）。

## 五、诚实兜底（主动承认，反而加分）

**Q15：最大弱点 / 还有什么没解决？**
> 三个诚实边界：① S5b 的 demo 用 `MarketState` 代指链上状态，生产换真实池子状态；② 模型的"语义正确性"是治理问题不是密码学问题；③ L2 重组风险。全写在 SECURITY.md。

**Q16：数据过期 / 新鲜度？**
> receipt 有 `executedAt` + stateProof 有 `blockNumber`，验证时检查新鲜度（≤5min）和时序（数据不得晚于执行）。

**Q17：为什么是你们团队？**
> 我们已经在做"验证/证据"这条线（TraceQuay 的安全审计、riftmark 的 run-evidence），这是把同一套 DNA 下沉到"agent 管钱"场景，补上密码学授权 + 链上锚定 + 机器支付。
