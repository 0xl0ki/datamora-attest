## 0. 开场（30 秒）—— 问题

> （操作：VM 浏览器打开 `http://127.0.0.1:9292`，停在首页/终端视图）

各位评委好，我是 [你的名字]，来自 Datamora。

2026 年最大的变化是：**AI Agent 开始自己管钱了**。
但问题随之而来——Agent 替你发现机会、执行交易的时候，你凭什么相信它：

- 它**真的**看了链上的数据吗？
- 它**真的**按模型算出了结果吗？
- 它**真的是你**授权的吗？

过去，这些问题只能"信平台"。我们的项目 **Datamora Attest**，把它变成"**信密码学和链本身**"。

## 1. 一句话方案（30 秒）

> （操作：鼠标滑过侧边栏九个视图，展示项目全貌）

我们把 Agent 的一次执行，打包成一条**带证据的收据**——receipt。
一条收据里绑定四种证据：**授权、输入来源、推理计算、链上锚定**。
任何人、任何机器，都可以**离线独立验证**——不需要信任我们、不需要注册表。

---

## 2. 现场演示（90 秒）

> （操作：走终端一键演示导览，或按顺序手动点击）

**① 封存与验真。** 点 SEAL，生成一条收据。然后我改一个字节——VERIFY 立刻报错。篡改检测，SHA-256 内容寻址。

**② 授权。** EIP-712 签名，把操作者、策略哈希、Agent 代码哈希绑在一起。签名用的私钥……一会儿大家会看到它藏在哪里。

**③ 推理证明。** 两层：第一层，模型公开，任何人重算 `output == model(input)`；第二层，**零知识**——我们用 EZKL 把模型编译成 Halo2 电路，生成真实 ZK 证明，`verified: true`。证明 AI 没有瞎编一个数。

**④ 数据来源。** EIP-1186 链上存储证明。我们没有调任何库——**自己实现了以太坊 MPT 验证器**，证明模型的输入真的来自链上状态，不是 Agent 自己声称的。

**⑤ 链上锚定。** 一堆收据折成一个 Merkle root，一笔交易钉上链。

## 3. 硬件 —— 授权的那把钥匙（60 秒）

> （操作：拿起 ESP32 板子；网页端生成一笔授权请求）

前面说"授权"，私钥到底在哪？**在这个东西里。**

> （操作：展示板子屏幕 → 屏上显示 datamora 授权摘要 → 手指点签名 → 网页端显示验证通过）

这是一块 ESP32 硬件钥匙。固件基于开源的 OSKey（MPL-2.0），我们定制了 **datamora 品牌与主题**——现在整块屏都是我们项目的视觉。
私钥在设备内、永不进软件。

评委请看屏幕：Agent 哈希、策略哈希、链 ID。我点一下确认——签名回到系统，验证恢复出的 operator，就是这台设备的地址。

**"可验证的授权"，从 PPT 上的抽象概念，变成眼前的一次物理动作。**

# 附：评委常见问题速答

| 问题 | 回答要点 |
|---|---|
| 你们和一般的审计/存证项目有什么区别？ | 不是事后审计，是**执行时就把证据做进收据**；跨主体可验证，不依赖平台数据库。 |
| "可验证"的信任根是什么？ | 收尾信任根是 **Robinhood Chain 共识**；授权信任根是签名者地址；计算信任根是 EZKL 电路。每层都有明确的信任假设（SECURITY.md 里写明）。 |
| ZK 证明是真的吗？ | 真的。EZKL 编译 ONNX 模型 → Halo2 电路 → 生成/验证证明，`verified: true`；同时有确定性复算路径兜底。 |
| 硬件固件是不是照搬 OSKey？ | 基于 OSKey（MPL-2.0，已按许可证署名 + fork 公开源码），但做了六项定制：主题、品牌、Logo、触摸修复、启动修复、双核渲染优化。 |
| 生产环境还差什么？ | 诚实说：① S5b 用真实池子状态槽证明替换 demo 夹具；② x402 支付接真实链上转账；③ 硬件密钥用安全芯片。都在路线图里。 |
| 为什么选 Robinhood Chain？ | 黑客松指定场景；Arbitrum Orbit L2、ETH gas，主网真实部署成本低（每笔锚定约 $0.01），适合高频存证。 |
